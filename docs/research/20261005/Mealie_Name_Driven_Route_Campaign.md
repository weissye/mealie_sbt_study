# Engineering and research protocol: name-driven route identity

## Motivation and qualification boundary

The preserved direct-slug campaign changed slug while retaining name. Pinned Mealie v3.28.0 repository update logic retains the existing slug when name is unchanged. The campaign consequently stopped at a requested alias returning 404 before collecting old-route reads. That result remains unqualified until reads on the original home database. The work read-only audit found all 28 archived resources unavailable; this is an environment observation, not a new defect.

## New mechanism and hypotheses

This campaign changes the documented writable name field that drives routing. Stable recipe UUIDs must survive the two successive renames. A linked recipe and shopping lists must preserve reference targets and quantities. Retired aliases must return 404. When a third separately owned recipe acquires the original name, the old alias must resolve to that third UUID while existing references remain attached to the original UUID.

Two control schedules and two schedules per mechanism are replayed with fresh resources. Logical task order variation is generated by Provengo; HTTP requests remain sequential. Prefix construction establishes shared food/unit ingredients and shopping-list associations before the route-specific tasks. This is a scoped mechanism test, not complete graph coverage or a randomized sample of all API operations.

## Evidence before verdict

Each route phase captures one exact request body and one raw PUT response. It then collects old-alias and new-alias reads and six full referrer bodies before validation. The subsequent validations independently check full target state with only declared timestamp and instruction-row UUID variation, protected referrer projections, quantities and reference identities. There are nine raw observations per completed phase, eighteen per completed route task. Sixteen extra GETs per schedule close the previous evidence gap.

The independent Python validator requires the expected observation count, exact change in the write body, documented write success status, agreement of raw new-route reads with the validated target, correct old-route status and identity, and agreement of raw referrer projections with semantic checks. Missing or forged evidence is rejected. Instruction row IDs may be recreated only under the existing explicit policy; content, array cardinality/order, recipe UUIDs and other references remain protected.

## Generic implementation and compatibility

The driver field and capture setting are explicit opt-in policy. Older profiles default to direct alias changes without capture. The new profile files have separate names and the previous runner is retained. No endpoint-specific branching was added to the compiler. The local native mock models name-driven persistence only when that policy is selected and retains its legacy behavior otherwise.

## Reporting

Preserve the first failing native schedule, response bodies, generated source, plan, seed, raw evidence and SHA256. Repeat the candidate on newly created resources. Deduplicate failures by violated invariant and causal mechanism; multiple failing schedules are reproductions of one defect. Do not report authentication, transport, missing-resource or oracle-policy failures as confirmed application bugs.

No full reset/replay, live production execution, exhaustive topology coverage or new bug confirmation is claimed by this release. The Downloads campaign is the review artifact; it is not automatically pushed as findings before classification.
