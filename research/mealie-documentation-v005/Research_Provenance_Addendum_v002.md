# Original Mealie discovery automation — provenance review v002

Review date: 9 October 2026. This is a read-only historical audit, not a new live run.

## Answer to the research question

The original discovery campaigns did automate contract-bound JavaScript compilation, prerequisite construction, native Provengo schedule sampling, regular-actor execution, runtime ID binding, evidence capture and candidate evaluation. Later curated reproductions do not invalidate that original automation. However, the original actor programs and expected outcomes were supplied as explicit profiles. The retained evidence supports **automated detection through a profile-driven OpenAPI compiler and native Provengo**, rather than autonomous inference of all test intent from OpenAPI alone.

The two meanings of automatic must therefore be separated: discovering a previously unknown server deviation during an automatically executed, predeclared test program is supported; automatically inventing the semantic test program without reviewed policy is not demonstrated by the retained campaigns. Predeclared negative expectations are not evidence that the server defect itself was known before execution.

Inspection of the retained profiles and first live plan for each of four configurations shows identical ordered step IDs and identical check declarations. The plans add request-schema data and show two body differences per case; they are not byte-identical to the input profiles. The detailed JSON audit records these differences instead of claiming an exact source-to-output recompilation.

## The invalid-JS statement needs temporal qualification

All eight retained original campaign executions have native_exit 0 and LIVE_CALLBACKS_COMPLETE, with response counts matching task counts. Thus the assertion that the JS was invalid during those accepted discovery runs is contradicted by their execution records. Earlier callback failures and later reconstruction errors are separate stages. Full callback success is stronger than a syntax-only check, but still does not establish exhaustive correctness of every generator mode or oracle.

## A defensible complete research narrative

Use the historical contract/profile/compiler/sample/receipt chain to explain original generation and detection. Use the existing independent state analyses and server traces to qualify F04/F05. Use the newer native execution evidence as a separate replication lineage. Distinguish generation lineage, execution acceptance and failure-path equivalence; do not silently replace historical JS with newer JS and label the result one original run.

To establish equivalence of a future replacement compiler, the missing evidence is a recorded correspondence of declared tasks, actor bindings, prerequisites and oracle semantics, plus native acceptance and regression evidence. Combining two sets of files alone would not establish that correspondence. No new boundary-replay compiler or live exploitation workflow is created by this audit.

## Search scope and remaining uncertainty

The review examined both original finding archives, their nested campaign outputs, the retained source snapshot, and the GitHub main checkout plus the two named source commits. Conversation-history retrieval failed; this report therefore relies on actual artifact and code records, not an invented reconstruction of conversation text. No earlier matching discovery than the two named campaigns was established in this review. Global novelty, comparative tool superiority, true HTTP concurrency and OpenAPI-only semantic discovery remain unsupported.
